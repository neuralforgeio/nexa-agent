## Masalah: Ornith tidak support function calling

### Root cause

Ornith (`llama-server.exe --jinja`) tidak mengembalikan struktur `tool_calls` dalam response. Dari log streaming:

```json
{"delta": {"reasoning_content": "Thinking"}}  // ← reasoning only, no tool_calls
{"delta": {"content": "I'm Gemini..."}}         // ← plain text, no function name/arguments
```

LLM tidak akan call tool via function-calling format. Ini adalah **limit model**, bukan bug Nexa.

### Workaround (Tools masih bisa dipakai)

**Opsi 1: Direct tool invocation** (recommended untuk Ornith)
```python
from tools.registry import create_default_registry

reg = create_default_registry()
# Write file direct (bypass LLM)
result = await reg.execute('write_file', path='output.txt', content='Hello!')
# Read back
read_result = await reg.execute('read_file', path='output.txt')
```

**Opsi 2: Tool prompt enhancement (future)**
Add stronger function-calling formatting ke system prompt (prompt Ornith untuk output JSON dengan exact structure.

**Opsi 3: Model upgrade**
Upgrade Ornith ke versi yang support function calling (Hermes 3, Mixtral 8x7B, or newer Qwen2.5 dengan instruct-tuned untuk tools).

## Quick Start untuk Ornith + Nexa

### 1. Add Ornith provider (sekali saja)
```bash
nexa provider add ornith \
  --base-url http://127.0.0.1:8080/v1 \
  --api-key dummy \
  --model "Ornith-1.0-9b-Q4_K_M.gguf"
nexa provider use ornith
```

### 2. Test connection
```bash
nexa provider test ornith
# ✓ ornith is healthy (responded 200).
```

### 3. Start Nexa + Ornith
```bash
# Terminal 1: Backend (port 8000)
nexa gateway start

# Terminal 2: Frontend (port 3000)
cd nexa_web && npm run dev
```

### 4. Chat via Web UI (localhost:3000)
```
[You]: Write a React app to nexa-workspace/myapp.html
[Nexa]: (akan panggil tools — tapi Ornith tidak support, akan produce plain text)
```
**Issue**: Tanpa function-calling support, agent akan reply plain text dengan instruksi manual.

### 5. Chat via CLI (recommended untuk Ornith)
```bash
nexa-chat
nexa > /provider use ornith
nexa > Hello, write a Python factorial function
nexa > Can you save that code to a file?
nexa > /exit
```

## Cara Verifikasi Tools Langsung (bypass LLM)

```bash
cd nexa-agent
.venv/Scripts/python.exe -c "
import asyncio
from tools.registry import create_default_registry

async def test():
    reg = create_default_registry()
    # Write
    w = await reg.execute('write_file', path='test.html', content='<h1>Hello</h1>')
    print('write_file:', w.ok)
    # Read
    r = await reg.execute('read_file', path='test.html')
    print('read_file:', r.ok)
    # UUID
    u = await reg.execute('generate_uuid')
    print('generate_uuid:', u.ok)

asyncio.run(test())
"
```

## Troubleshooting

| Issue | Penyebab | Solusi |
|-------|----------|--------|
| `Missing credentials` | Ornith no API key set | Set `api_key='dummy'` di `--api-key dummy` |
| Streaming 5+ menit untuk respons singkat | Laptop tua + model 9B | Normal. Pakai `max_tokens=512` |
| Model tidak generate tool_calls | Ornith limitation | Pakai tools langsung via Python API |
| `404 Not Found` di Web UI | Backend tidak running | `nexa gateway start` |
| Frontend error `fetch failed` | Backend down | Check http://127.0.0.1:8000/api/health |
| Install gagal (`winget not found`) | Windows older version | Manual install: https://python.org |

## Performance Notes

- **Latensi 314.7s** untuk respons kompleks (tools + JSON parsing) — normal untuk Ornith 9B Q4_K_M di 4 CPU threads.
- Untuk iterasi cepat, gunakan **small atau code_execution model** via `--n-predict 512` (limit tokens).
